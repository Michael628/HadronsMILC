# Autoresearch ideas — HadronsMILC

## Landed
- `422c7aa` — fuse SUM/DIFF axpy pairs (2 kernels/eigenpair → 1): 18.91 → 9.13 ms.
- `012f1e3` — fuse across color columns (6 accumulators, 3·nEigs → nEigs kernels/output): 8.44 → 7.37 ms. Accumulation is no longer the dominant per-output cost on 4^4.
- `77a71ca` — batch four eigenpairs per kernel launch (nEigs → nEigs/4 launches; bit-identical ordering).
- `86307b1` — fuse per-column assembly (−i axpy + 2× setCheckerboard + sol scale → ONE full-grid kernel/column; bit-identical, witness sha256-gated): bench8 interleaved A/B min 9.94 → 9.62 ms, median 12.13 → 9.82 ms, 4/5 pairs. Small on 4^4 CPU but strictly-less-work; pays more on GPU (launch overhead) and large volumes (sol bandwidth).

## Verified-but-discarded (run #9)
- **rbFermNeg zero-init before Meooe**: Meooe DOES fully overwrite its output (ImprovedStaggeredFermion::Meooe → DhopOE/EO → DhopImproved opens out AcceleratorWrite, DhopSiteGeneric coalescedWrites every site; first stencil leg assigns, never reads out) — proven by source AND by bit-identity with stale buffer content. But removing it moved the metric −0.2% (noise floor ~1 ms): discarded. Reapply the one-line removal only if a production-lattice profile shows the per-column tail dominating.

## Open ideas (bench8: 4^4 real config, nEigs=60, 8 outputs — module ~10 ms)
- **First-iteration write instead of 6 accumulator Zero()s**: the k-loop's first eigenpair (k = eigStart+nEigs−1) could write `coef·ev` unconditionally instead of `coef·ev + read(acc)`, deleting all six zero-init kernels per output. Caveat: `x + 0.0` vs `x` differs on signed zeros — numpy-value gates pass but strict bit-identity would not; the bit-identity gate is now routine (witness sha256 protocol), so this needs a deliberate decision to relax to value-gates. Batches of 4 make it slightly fiddly: the FIRST batch (highest k) writes, all later batches accumulate.
- **rbFermNeg zero-init before Meooe**: removal proven safe and bit-identical (run 9; Meooe fully overwrites). Sub-noise alone on 4^4 but compounds with tail work — reapply as a drive-by with the next tail change; it is now one line inside the fused-assembly region.
- **Meooe batching across color columns**: 3 Meooe calls/output on three different accumulators; if the stencil API exposes a multi-RHS or batched call, kernel count drops 3→1. Check ImprovedStaggeredFermion/MdagM interfaces first.
- **outputName()/gammaList() parse hoisting** (re-parses per name; ~2 calls/output in execute()): sub-noise on 4^4, grows with output count; pure hygiene — poor autoresearch candidate, fine as drive-by cleanup.
- **Bigger benchmark, revisited**: bench8 (4^4 real config, Nstop=60, tA..tB full, gitignored under test/work/bench8/) resolves ~5% module changes ONLY with interleaved A/B. A true 8^4+ benchmark needs a REAL (non-free) 8^4 gauge config — free-field 8^4 IRL is pathological under Cheby(0,24) (0/60 converged, 46 min, abort). If a real 8^4 config appears, redo the harness at 8^4 with the same module wiring.
- **Grid view-family exclusivity (lesson for custom kernels)**: a buffer's Accelerator-mode views must ALL close before any CPU-mode view (setCheckerboard, reductions, transfers) opens on it — `MemoryManagerCache.cc` asserts. Scope hoisted views tightly.
- **autoView macro pitfall**: `autoView(n, *ptr[i], mode)` expands to `*ptr[i].View(mode)` — `.` binds tighter than `*`; bind a named reference first (hit again in 86307b1's sumR view).
- **Harness pitfalls**: Hadrons output directories (`file.20/`, `ref.20/`) collide across schedules — snapshot per-schedule subdirs; the two schedules' `ref.20` datasets legitimately differ. Box noise is heavy — interleaved A/B with BOTH binaries preserved (cp the two builds, alternate per run) is the only protocol that survived the batch-order confound; single-arm min-of-3 batches once inverted a verdict. /tmp is wiped between turns — keep scratch harnesses inside the repo (gitignored test/work/…). Bit-identity gate protocol: snapshot witness HDF5 dataset sha256s (multigamma g1/g5/conj/ref + file-compare file/ref) before the change, compare after.

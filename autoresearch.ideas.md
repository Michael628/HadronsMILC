## Verified-but-discarded (run #9)
- **rbFermNeg zero-init before Meooe**: Meooe DOES fully overwrite its output (ImprovedStaggeredFermion::Meooe → DhopOE/EO → DhopImproved opens out AcceleratorWrite, DhopSiteGeneric coalescedWrites every site; first stencil leg assigns, never reads out) — proven by source AND by bit-identity with stale buffer content. But removing it moved the metric −0.2% (noise floor ~1 ms): discarded. Reapply the one-line removal only if a production-lattice profile shows the per-column tail dominating.

## Open ideas (bench8: 4^4 real config, nEigs=60, 8 outputs — module ~8.5-9.5 ms)
- **Meooe batching across color columns**: 3 Meooe calls/output on three different accumulators; if the stencil API exposes a multi-RHS or batched call, kernel count drops 3→1. Check ImprovedStaggeredFermion/MdagM interfaces first. Now the LAST remaining per-column kernel (with FermToProp).
- **FermToProp fusion into the assembly kernel**: the assembly kernel writes sol; FermToProp then extracts color column c into prop. If FermToProp's element-wise insert could be folded into the assembly pass (write directly into prop's column), one more kernel/column goes. Requires PropagatorField layout knowledge (3×3 color matrix per site) — same class of cross-layout indexing as the assembly kernel; witness-gate it.
- **Bigger benchmark, revisited**: bench8 (4^4 real config, Nstop=60, tA..tB full, gitignored under test/work/bench8/) resolves ~4-5% module changes ONLY via quiet-mode floors under interleaved A/B. A true 8^4+ benchmark needs a REAL (non-free) 8^4 gauge config — free-field 8^4 IRL is pathological under Cheby(0,24) (0/60 converged, 46 min, abort). If a real 8^4 config appears, redo the harness at 8^4 with the same module wiring.
- **Grid view-family exclusivity (lesson for custom kernels)**: a buffer's Accelerator-mode views must ALL close before any CPU-mode view (setCheckerboard, reductions, transfers) opens on it — `MemoryManagerCache.cc` asserts. Scope hoisted views tightly.
- **autoView macro pitfall**: `autoView(n, *ptr[i], mode)` expands to `*ptr[i].View(mode)` — `.` binds tighter than `*`; bind a named reference first (hit again in 86307b1's sumR view).
- **Harness pitfalls**: Hadrons output directories (`file.20/`, `ref.20/`) collide across schedules — snapshot per-schedule subdirs; the two schedules' `ref.20` datasets legitimately differ. Box noise is HEAVY and BIMODAL (quiet ~9 ms mode vs contended 15-27 ms): pairwise A/B wins are meaningless; the discriminant is the per-arm quiet-mode floor (min + floor-cluster mean) over interleaved pairs — single-arm batches once inverted a verdict. /tmp is wiped between turns — keep scratch harnesses inside the repo (gitignored test/work/…). Bit-identity gate protocol: snapshot witness HDF5 dataset sha256s (multigamma g1/g5/conj/ref + file-compare file/ref) before the change, compare after. accelerator_for captures are safe for value-captured `const bool` flags on both CPU (synchronous thread_for) and CUDA ([=]) paths.
